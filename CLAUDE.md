# Sundance: working notes

An isometric spaghetti-western stealth shooter in Godot 4.7 (GDScript). Every sprite and
sound is generated by the Python tools; nothing is hand-drawn. [DESIGN.md](DESIGN.md)
describes how the game works, system by system; [README.md](README.md) has the controls,
asset commands, test list and debug flags. Read the DESIGN.md section for a system before
changing it.

## How we work

- Features come one at a time, from the user. Ask before starting when a design choice
  is genuinely theirs (feel, balance, what a gun should be); otherwise pick a sensible
  default and say so.
- Each feature: implement, test headless, look at it (screenshot or contact sheet),
  then update DESIGN.md, README.md (controls, test list) and memory.
- "Commit it" means a commit on main with a descriptive message. Never push.
- The user's backlog of ideas (and their decisions on built ones) is in Claude's
  project memory (`future-ideas.md`, `expansion-plan.md`). Raise a backlog idea when work
  touches a related system; don't build one unasked.

## Code conventions

- Comments and doc comments are prose in the game's voice ("the stranger", "the gang"),
  saying why and what it's like in play; match the surrounding density.
- Gun behaviour is data: `Weapon.DATA` in `scripts/weapon.gd`. Bandit types, loadouts and
  per-type tuning are data in `data/enemies.json`; levels and waves in `data/levels.json`.
- Anything random that tests replay must not draw on the global RNG if it's new: give it
  its own `RandomNumberGenerator`, seeded in `game.gd` under the `fixed_seed` meta (see
  `loot_rng`, `Enemy.rabble_rng`, `Enemy.return_rng`, `Enemy.schofield_rng`, `Civilian.rng`;
  `game.sfx` and `game.free_point_near` take a `dice` for this). Adding
  global `randf()` calls shifts every seeded test.
- Never let the wall clock (`Time.get_ticks_msec()`) decide anything that draws a
  random number, plays a sound (`game.sfx` draws two) or steers the AI: a headless test
  runs faster than real time alone and slower under load, so the dice come out
  differently. Use `game.clock` (game time). Wall clock is for visuals only.
- Type GDScript variables explicitly where inference fails (`var e: Enemy = ...`).
- Wave and stage logic belongs in `scripts/director.gd`, not `game.gd`.

## Testing

```bash
tools/run_tests.sh                                   # the whole suite, 8 at a time
tools/run_tests.sh tests/test_kegs.gd                # some of it
godot --headless --path . --fixed-fps 60 -s tests/test_pickups.gd   # one, output to the terminal
```

- Tests are `extends SceneTree` scripts with a `check()` helper, printing `FAIL: ...` and
  ending `... test: OK`. New features get a `tests/test_<feature>.gd` and a line in README.
- Engine metas switch things off for tests: `fixed_seed`, `level`, `no_civilians`,
  `no_reserve`, `no_downed`, `no_alarm`, `always_gasp`, `no_gasp`, `no_last_stand`,
  `no_hanging` (every test on the default San Miguel sets it, but test_hanging), `no_captive`
  (every Cruz Verde test sets it, but test_captive), `no_waves` (the Paso Esperanza tests of
  the place and the cargo set it; test_federales doesn't).
- A test that passes alone but fails in the suite is almost always the wall clock
  leaking into the game (see above), not luck: find it. test_perf is left out of the
  suite; it needs a quiet machine.
- A level's opening runs for a few seconds after `game.begin()` before the stranger can
  act: wait for it (or poll for what you need) rather than counting frames.

## Assets

```bash
tools/.venv/bin/python tools/gen_assets.py chars                 # all bodies (long)
SUNDANCE_TEMPLATES=hero,vest tools/.venv/bin/python tools/gen_assets.py chars
SUNDANCE_OBJECTS=keg tools/.venv/bin/python tools/gen_assets.py world
tools/.venv/bin/python tools/gen_assets.py fx ui sfx
godot --headless --path . --import                               # after any bake, or a new class_name script
```

- A new gun for bandits: its model in `weapon_model` and `GUN_LEN` (`tools/chars.py`),
  poses in `_key_poses`, animations in `upper_anims`; `template_guns()` works out which
  templates need it from enemies.json and levels.json. Re-bake those templates, then `fx`
  (the dropped-gun sprites); for the stranger, also `ui` (loadout card art) and the hero.
- Baking many templates takes 10+ minutes: run it in the background.
- The `ui` step rewrites `assets/sprites/ui/portrait.png` with small differences; restore
  it with `git checkout` unless the portrait was meant to change.

## Looking at it

- Screenshot the real game: `godot --path . -- --level=cruz_verde --skip-title --at=33,30
  --shot=out.png --shot-time=8`. For a staged moment, write a throwaway
  `tests/zz_shot.gd` (a SceneTree script that sets things up, then saves
  `root.get_viewport().get_texture().get_image()`), run it windowed (no `--headless`),
  and delete it afterwards.
- `tools/anim_sheet.py` makes a contact sheet of baked animation frames;
  `tools/map_plan.py` draws a map's layout on its tile grid (for placing things in
  `tools/make_*.py`).
- macOS: there's no `timeout`; zsh doesn't word-split a string in a `for` loop.
